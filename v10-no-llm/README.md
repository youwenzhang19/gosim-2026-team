# 历史附录：原包继承的 fix3 说明（不是本版结果）

以下原文仅用于保留历史背景；其中版本、分数、测试数量和修改范围不描述 v9.1。以 CHANGELOG_V9_1.md 和本版 validation/ 为准。

本目录是从 `v8-probe-fix2 (1).zip` 复制出的独立修正版。原 ZIP 和 fix2_1 解压目录保持不变。

## 本次修改

1. `planner.py` 不再按光纤目标数量保存 scale 样本，而是每次曝光只生成一个摘要；样本按模拟小时淘汰。40 个目标不会产生 40 票，也不会把一次曝光的顺序变成统计权重。
2. 新增 `scale_estimator.py`：
   - 饱和反馈只作为下界；不会把下界当成点估计压低已有测量。
   - 同一曝光的 clean 目标在曝光层汇总。
   - 节目倍率有歧义时保留区间状态，scale estimator 不使用 planner 的倍率猜测作为 exact 标签。
   - 新的 clean、有限区间反馈会及时更新当前 scale，不用旧曝光与新天气混合投票。只有下界或超过 2 小时没有当前反馈时，明确记录不确定状态，必要时安排短探针。持续收到饱和下界、但超过 1 小时没有有限区间反馈时，也会请求探针。
   - `dir_clean=False` 的方向性反馈不进入全局 scale，但会被写入诊断计数。
3. 删除旧的 0.05/0.01 估计托底；scale estimator 不设置物理点估计下限。小估计值会参与规划，可能改变目标排序和选区，不能保证与旧版规划相同。
4. `planner.factor` 对节目倍率不确定的结果取保守可能因子，避免用一次错误的 mismatch 判断把 required 目标标成完成。
5. 包内 `tests/test_planner_engine.py` 覆盖样本驱逐、天气突变、饱和下界、倍率歧义、方向污染、过期样本、严重效率下降、状态复位和自适应探针。

## 故障报修暂不改动

`agent.py`、`operations.py`、`llm_client.py` 均与输入包逐字一致；planner.py 中的 `clean_e` 函数也没有改。现有自动报修规则仍然保留，未新增规则，也未禁用；本次没有实现“全由 agent 决定报修”的架构迁移。诊断中的 legacy 字段保留原推断，仅供旧故障链路使用，不能视为新版 scale 的准确标签。scale estimator 只报告有效观测质量证据，不声称它是天气或仪器故障。

当前区间是两个合法节目倍率下的证据包络，不是概率置信区间；真实几何近似与未公告的方向差异仍可造成误差。只有饱和下界时无法辨识真实 scale；自适应探针也不保证一定未饱和。探针 15 分钟间隔是预算限制，不是 15 分钟准确保证。请勿将此版理解为已经解决仪器故障检测。

原因是同一个低 factor 可能来自天气、方向性事件、仪器效率、平场/镜盖测试或导星相机故障。planner 硬编码“低 scale 就报修”会把天气误报成故障，消耗免费/付费报告次数；硬编码“低 scale 不报修”又会漏掉持续故障。未来 agent 恢复后应由 agent 结合公告、时间、方向、连续性和维修历史判断。

区间估计明确保留节目倍率歧义，不靠假定仪器效率来宣称 exact；它可能比某些理想条件下的旧点估计更保守，所以相对误差中位数并未全面改善。八晚卡好条件的平均绝对误差也从约 0.00017 增为 0.05689，不过全部反馈仍处于 10% 内。不能把这两张卡的增分当成隐藏卡成绩保证。
